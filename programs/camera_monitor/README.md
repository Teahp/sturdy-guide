# Camera Monitor 并发摄像头监控程序

本项目将单线程摄像头采集程序重构为分层并发架构，在保持原有功能与交互逻辑不变的前提下，实现了采集线程与UI线程分离、有界帧缓冲区、跨线程异常传递与完整的线程安全保障，同时支持无硬件依赖的自动化测试。

## 环境依赖
- 操作系统：Ubuntu 22.04 及以上 Linux 发行版
- 编译工具：CMake 3.16+、Ninja、支持 C++17 的编译器（GCC / Clang）
- 依赖库：OpenCV 4.x、v4l-utils
- 一键安装依赖：
```bash
sudo apt update
sudo apt install -y libopencv-dev v4l-utils cmake ninja-build g++

## 构建方法
在 `camera_monitor` 根目录执行：
# 配置构建
cmake -S . -B build -G Ninja
# 编译
cmake --build build
编译产物位于 `build/` 目录，可执行文件为 `build/sturdy-guide-camera`。

### 运行自动化测试
cd build
ctest --output-on-failure

所有测试用例均不依赖真实摄像头硬件，可在任意环境执行。

## 运行说明

### 命令行参数

./build/sturdy-guide-camera [--device INDEX] [--width PIXELS] [--height PIXELS]

- `--device`：摄像头设备编号，默认值为 0，对应系统设备 `/dev/video0`
- `--width` / `--height`：采集分辨率，默认值为 1280×720

### 按键操作

- `S`：保存当前画面截图到程序运行目录
- `Q` 或关闭窗口：正常退出程序

## 架构设计

采用三层职责分离架构，各层单一职责，边界清晰，依赖单向。

### 1. 帧源抽象层 FrameSource

抽象摄像头采集能力，隔离硬件实现与业务逻辑：

- `FrameSource`：纯虚接口，定义统一的 `read()` 采集方法
- `OpenCvCamera`：基于 OpenCV `VideoCapture` 的真实摄像头实现
- `FakeFrameSource`：测试用模拟帧源，可生成可控的测试帧或模拟读取异常

### 2. 并发会话层 CameraSession

核心并发管理层，负责采集线程生命周期与状态管理：

- 通过 `std::unique_ptr<FrameSource>` 独占帧源所有权，真实设备与模拟设备可无缝切换
- 管理后台采集线程，实现 `start / stop / join` 完整状态机
- 维护容量为 2 的有界帧缓冲区，消费滞后时自动丢弃旧帧
- 通过 `std::exception_ptr` 实现后台异常跨线程传递

### 3. 应用层 PreviewApplication

运行于主线程，仅负责 UI 交互与画面展示：

- 调用 OpenCV 窗口接口完成画面渲染、帧序号与帧率叠加
- 处理键盘输入，响应截图与退出指令
- 不直接访问互斥锁与工作线程，仅通过 `CameraSession` 公共接口交互

## 线程安全契约

### 1. 对象资源与生命周期

- `FrameSource` 持有硬件设备或模拟数据生成器，所有权由 `CameraSession` 独占管理
- `CameraSession` 持有工作线程、互斥锁、帧缓冲区与异常指针，其生命周期由调用方保证，且长于内部工作线程
- `PreviewApplication` 持有 `CameraSession` 实例，生命周期与程序运行周期一致

### 2. 状态机与合法转换

`CameraSession` 包含四种状态，合法转换路径如下：

- **空闲态**：线程未启动，缓冲区为空
- **运行态**：工作线程运行中，持续采集帧
- **停止态**：已触发停止信号，线程正在退出
- **已回收态**：线程已 join，资源已释放

转换规则：空闲 → 运行（调用 `start()`）→ 停止（调用 `stop()` / 触发异常 / 对象析构）→ 已回收（执行 `join()`）→ 空闲（可重新启动）

### 3. 线程安全的公共接口

`start()`、`stop()`、`join()`、`try_get_latest_frame()`、`has_error()`、`get_error()` 均内部加锁，可被不同线程并发调用；析构函数不可与其他方法并发调用，由调用方保证对象生命周期的唯一性。

### 4. 互斥锁保护范围

- 保护成员：帧缓冲区 `frame_buffer_`、异常指针 `error_`、线程状态标记 `thread_joined_`
- 维护不变量：缓冲区大小始终 ≤ 2；异常一旦设置不可清除；状态转换为原子操作

### 5. 缓冲区满时的丢帧策略

缓冲区满时丢弃**最早的旧帧**，保留最新采集的帧。
原因：实时预览场景下，旧帧已失去时效性，用户始终需要最新画面；该策略可保证最低显示延迟，同时避免缓冲区无限增长导致内存溢出。

### 6. 禁止持锁执行慢速 IO

`VideoCapture::read()` 为硬件阻塞操作，`imshow()` / `imwrite()` 涉及 GUI 渲染与磁盘 IO，均属于耗时不确定的慢速操作。持锁执行会导致其他线程长时间阻塞，破坏并发性，甚至引发死锁。因此锁仅用于保护快速的内存状态转换，所有 IO 操作均在临界区之外执行。

### 7. 跨线程异常传递机制

采用 C++ 标准 `std::exception_ptr` 实现异常跨线程传递：
后台采集线程捕获异常后，将异常指针保存到共享状态；主线程调用 `try_get_latest_frame()` 时检查异常状态，若存在异常则在主线程重新抛出，保证调用方可以在同一上下文统一处理错误。

### 8. 析构执行顺序

对象析构时严格按照 **设置停止标志 → 唤醒等待线程 → 等待线程 join 回收** 的顺序执行。
先通过原子标志通知工作线程主动退出，再等待线程执行完毕回收资源，最后销毁成员变量，避免野线程访问已销毁的对象。

## 自动化测试

基于 `FakeFrameSource` 实现无硬件依赖的单元测试，覆盖 7 项核心场景：

1. 启动后帧序号按序递增
2. 重复调用 `start()` 幂等安全
3. 连续调用 `stop()` 不崩溃、不死锁
4. 对象析构前自动完成线程 join
5. 消费速度较慢时缓冲区大小不超过 2，按策略丢帧
6. 后台采集异常可在主线程被观察到
7. 空帧不会被发布为有效画面

所有测试通过 CTest注册，支持一键执行。
```
